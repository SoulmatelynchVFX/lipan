# 璃盘 · Lipan

让电脑存储像手机一样容易理解：不仅知道空间被占了多少，还知道它属于谁、用来做什么，以及处理它可能带来什么影响。

璃盘面向 Windows，目标是做一个**以应用和内容为中心的只读存储分析工具**。它提供条目、解释和判断依据，是否清理完全由用户决定，不执行删除或卸载。

> 项目处于原型阶段。仓库现已提供只读命令行基础模块，其余章节描述产品目标与边界，不是完整的已交付功能清单。网页界面、全盘归属和历史对比尚未随本模块发布。

## 当前可运行的基础模块

需要 Python 3.11+，无需第三方依赖。在仓库根目录运行：

```powershell
# 读取 Windows 应用清单，不扫描应用目录
python -m storage_inspector --list-apps

# 只统计明确指定的文件或目录
python -m storage_inspector --path "D:\Example"
```

输出为 JSON，不自动保存或上传。统计会跳过遇到的链接及离线属性项，对硬链接去重，并报告访问失败。文件逻辑长度不等于磁盘实际分配量，更不代表可清理容量；本版不汇总应用全部占用。

应用清单保留同名软件的不同版本和安装位置；读取注册表失败时返回错误明细和部分结果标记，不将缺失信息当作完整清单。

使用说明、限制与测试命令见 [只读基础工具](docs/storage-inspector.md)。

## 为什么做璃盘

电脑上的空间往往散落在安装目录、AppData、ProgramData、文档、下载和其他磁盘中。单看文件夹大小，很难回答几个实际问题：

- 一个软件连同缓存、插件、模型和用户数据，到底用了多少空间？
- 某个十几 GB 的目录是什么，处理后会丢什么、影响什么？
- 软件装完后留下的材料，还用于修复、卸载或离线重装吗？
- 最近空间增长在哪里，即使这个软件没有被规则库收录，能不能继续分析？

璃盘希望补上“看见占用”到“理解占用”之间的这一层，而不只是换一种方式排列文件夹或已安装程序。

## 我们希望做到什么

### 1. 看见全部磁盘，而不只是安装清单

以磁盘实际用量为起点，展示已扫描空间、访问受限内容和未对齐的差额。无法归属的文件仍应保留在结果中；差额不能被隐藏，也不能当作可清理容量。

### 2. 按应用与内容组织空间

把分散路径尽可能关联到应用，并区分程序本体、缓存、日志、设置、下载内容、模型、用户作品和共享数据。同一份数据不重复计入多个应用；无法确认的关联明确标为推断。

### 3. 解释用途、影响和处理条件

每个条目应尽量回答三件事：**它是什么、处理它有什么影响、需要先核对什么。**

- **高风险、需要人工复核**：系统文件、运行依赖、设置、账号数据、工程资料及可能影响修复或卸载的内容。
- **低风险缓存候选**：需要有可重建依据，并说明重新下载、重新生成或首次运行变慢等代价；目录叫 `cache` 不等于已经验证安全。
- **安装后可能不再需要的材料**：必须核对安装是否完成、是否还被维护流程依赖，以及是否需要离线重装，不能一概认定无用。
- **用途不明的内容**：给出已有线索、缺少的证据和下一步核对方式，不伪装成确定结论。

“归属判断有把握”和“处理风险低”是两回事，必须分开表达。

### 4. 没有规则，也能提供帮助

已知规则用于提高解释精度，但不应成为能否分析的门槛。结合安装清单、启动器清单、路径关系、文件类型、下级目录和扫描前后变化，帮助用户逐步理解未收录软件留下的空间。

不知道所属应用，不等于只能显示“无法分析”；同时，线索不足时也不能强行猜一个归属。

### 5. 加入有依据的 AI 建议

AI 的目标是把扫描事实和规则证据转成简短、具体的解释，指出可能的用途、风险和需要人工复核的地方，而不是替用户决定删除。

建议应区分扫描事实、已核验规则和 AI 推断，说明不确定性。AI 不能把未知目录直接判为可删，也不能把“可能是安装材料”改写成“安装后已经没用”。**AI 建议尚未接入，不把本地路径提示称作 AI。**

### 6. 简洁呈现，不做长篇检查报告

界面采用圆角玻璃风格，信息分层展开：

1. 默认看名称、占用和风险提示。
2. 展开看用途、影响和建议。
3. 需要核实时，再看路径、来源、归属依据和扫描说明。

支持按占用、增长和关注内容筛选。细节必须可查，但不应一次全部堆到用户面前。

## 如何逐步实现

- **扫描与核对**：建立完整的空间视图，区分实际分配空间与文件逻辑大小，处理共享路径、硬链接及访问失败。
- **归属与解释**：结合清单、规则与通用线索；为每条判断保留来源、适用范围和不确定性。
- **规则维护**：为规则记录软件版本、路径范围、用途、处理影响、证据和验证日期；未经验证、失效或有冲突的规则不得冒充安全结论。
- **变化追踪**：通过本机扫描快照比较空间变化；没有进程监测证据时，不声称知道哪个进程写入了文件。
- **AI 辅助**：在证据基础上生成短建议，使用前明确告知发送哪些信息，并提供不用 AI 也能查看和分析的基础体验。

项目的长期价值不只在规则数量，而在于：规则可维护、判断可追溯、未收录内容仍有分析路径，最后用用户能读懂的方式呈现。

## 不变的边界

- **只分析，不执行清理**：不自动删除、不代替用户卸载，也不把风险标签当作删除许可。
- **本地优先**：基础扫描与历史记录在本机处理。接入外部 AI 前需要明确同意，并尽量减少、脱敏发送的信息；不默认上传文件内容或完整个人路径。
- **不承诺 100% 归属准确**：Windows 软件可以跨目录存储、共用资料或使用自定义位置，未知和冲突必须如实保留。
- **不制造“可释放空间”数字**：未经核验的缓存、安装材料和统计差额，不能直接加总成可清理容量。

## 当前进度与下一步

仓库已整理出应用清单和指定路径统计的独立基础模块。本地原型中的只读全盘扫描、扫描历史、归属线索、下级目录检查和分层展示仍待整理；不意味着完整应用已发布，也不意味着所有用途和风险已核验。

后续将逐步整理应用级跨目录归属、条目用途与影响、规则验证等能力。可安装的完整应用和有隐私控制的 AI 建议尚未交付。
